# AI가 계산하는 방식을 흉내 내는 작은 계산기 만들기

## 실행 방법
- `python3 main.py`
- 모드 선택: 1(사용자 입력 3x3) 또는 2(data.json 분석)
- data.json 위치: main.py와 동일 디렉토리

## 구현 요약
- 라벨 정규화: expected('+', 'x'), filter 키('cross', 'x') → 표준 라벨(Cross/X)로 통일. `normalize_label` 함수로 분리해 판정/비교 시 일관성 확보.
- MAC 연산: 이중 반복문으로 위치별 곱셈 후 누적 합산(`mac_operation`), 외부 라이브러리 미사용.
- 동점 처리 정책: `abs(score_a - score_b) < 1e-9`(epsilon) 이면 UNDECIDED(모드2) / 판정 불가(모드1).

## 결과 리포트

data.json 6개 케이스 중 3개는 PASS, 3개(size_5_1, size_13_2, size_25_1)는 FAIL.

각 케이스의 Cross/X 점수를 출력해서 확인한 결과, FAIL 3건 모두 원인이 동일. size_5_1의 경우 Cross 점수가 0.9, X 점수가 0.8999999999999999로 나옴 — 필터 값에 0.1, 0.3, 0.9처럼 2진수로 정확히 표현되지 않는 소수가 포함되어 있어, 계산 과정에서 반올림 오차가 발생. 수학적으로는 두 점수가 같아야 하나 부동소수점 연산 특성상 미세하게 어긋남.

데이터/로직/수치비교 세 가지로 나눠서 원인을 분리:
- 데이터·스키마 문제 아님. 필터와 패턴 크기 일치, 로드·검증 단계도 정상 통과함.
- 로직 문제 아님. MAC 연산 자체는 정상 수행되어 점수가 산출됨.
- 결국 수치 비교(부동소수점) 문제로 확인됨. epsilon 비교(`abs(score_a - score_b) < 1e-9`)가 없었다면 X > Cross로 잘못 판정될 뻔했으나, epsilon 적용으로 "사실상 동점"임을 정확히 잡아냄. 다만 요구사항상 UNDECIDED는 FAIL로 집계하기로 했으므로, 판정 자체는 맞았어도 결과는 FAIL로 남음.

즉 이번 FAIL은 코드 결함이 아니라, 필터 값 설계(부동소수점 소수 사용) + epsilon 정책이 맞물려 발생한 결과. 동점 상황을 검증하기 위해 의도적으로 넣어둔 값으로 판단됨.

시간 복잡도: MAC 연산이 N×N 이중 반복문 구조이므로 연산 횟수는 N²에 비례 — O(N²). 실제 측정한 성능 표(3x3~25x25)에서도 크기가 커질수록 평균 시간이 증가하는 경향을 확인함. 다만 3x3, 5x5처럼 매우 작은 크기에서는 연산 자체보다 함수 호출 오버헤드 비중이 커서, 완벽한 N² 비례 그래프로는 나타나지 않을 수 있음.
